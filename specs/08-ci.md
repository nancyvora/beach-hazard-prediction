# Spec 08: Continuous integration (lint, tests, smoke run, data guard)

## Goal
Run the checks automatically on every push and pull request so a change cannot
quietly break the pipeline, leak future data into training, or commit the raw
data. Answers: "Does the project still work, from a clean machine, right now?"

## Input
- The repository as it stands after specs 01–07: `src/`, `tests/`, `docs/`,
  and the pinned dependency file.
- Small committed fixtures in `tests/fixtures/` (for example the fixture
  parquet spec 04 already uses). **No real data.** The raw
  `beach-monitoring-results.csv` (~1.7 GB) and everything under `data/` are
  never read or downloaded in CI.

## Rules
- Read docs/decisions.md first. Do not change any decision there. CI checks
  the decisions (time split, limit, train-only fitting); it does not redefine them.
- CI runs on **GitHub Actions**, one workflow: `.github/workflows/ci.yml`.
- Triggers: `push` to `main`, and `pull_request` targeting `main`.
- Python version and dependencies come from the project's pinned files only.
  Do not pin a second copy of versions inside the workflow.
- **No network data, no secrets.** Tests must pass with `data/` absent.
  `MLFLOW_TRACKING_URI` is set to a temporary local folder
  (`file:${{ runner.temp }}/mlruns`). Never point CI at a remote tracking
  server, and never put credentials in the workflow.
- Everything CI runs must also run locally with the same commands (see
  Commands). No CI-only logic hidden in YAML.
- Fixed random seeds for anything stochastic, so CI results are repeatable.
- The whole workflow should finish in under 10 minutes. Cache pip downloads.

## Jobs
Jobs run in parallel. A pull request is mergeable only when all of them pass.

1. **lint**: "the code is clean and consistent."
   - `ruff check .` and `ruff format --check .`
   - Ruff settings live in `pyproject.toml`, not in the workflow.
2. **test**: "every unit and acceptance test passes."
   - `pytest -q` over the whole `tests/` folder (this includes the spec 04
     tests: split, metrics, baselines, MLflow fixture run).
   - Print a coverage report (`pytest --cov=src`). It is reported, not
     gated, for now.
3. **smoke**: "the training entry points run end to end."
   - Copy the fixture features file to `data/processed/features.parquet`,
     then run `python -m src.models.train_baselines` and the spec 05 training
     entry point against the temporary MLflow folder.
   - Pass only if each command exits 0 and the expected MLflow runs exist
     (3 baseline runs tagged `spec=04`, plus the spec 05 runs).
   - Does not check score values. Fixture scores are meaningless; the job
     checks that the plumbing works.
4. **data-guard**: "no data or large files get committed."
   - `python scripts/check_repo_files.py` fails if any tracked file:
     - is under `data/` (other than `.gitkeep`), or
     - is a `.csv` / `.parquet` / `.pkl` / model file outside `tests/fixtures/`, or
     - is larger than 5 MB.
   - Lists every offending path in its error message.

## Commands
- `ruff check . && ruff format --check .` (lint)
- `pytest -q --cov=src` (test)
- `bash scripts/smoke.sh` (smoke; the CI job calls this same script)
- `python scripts/check_repo_files.py` (data-guard)

## Files
- `.github/workflows/ci.yml`: the four jobs above
- `scripts/smoke.sh`: sets a temporary `MLFLOW_TRACKING_URI`, stages the
  fixture, runs the entry points, and checks that the runs exist
- `scripts/check_repo_files.py`: the data/large-file guard
- `pyproject.toml`: ruff config (add if missing)
- `README.md`: CI status badge, plus the four commands for running checks locally

## Output
- A green CI run on `main` for the commit that adds this spec's files.
- Each pull request shows four status checks: `lint`, `test`, `smoke`,
  `data-guard`.

## Acceptance tests (tests/test_check_repo_files.py, plus manual checks on a throwaway branch)
- `check_repo_files`: a file under `data/raw/` fails; `data/.gitkeep` passes;
  a `.parquet` in `tests/fixtures/` passes; a `.parquet` in `src/` fails;
  a 6 MB file anywhere fails; the error names every offending path.
- The test suite passes with no `data/` folder present (run `pytest` in a
  fresh clone).
- No test opens a network connection or reads `MLFLOW_TRACKING_URI` from a
  real server (the tests use the temporary folder).
- Manual: a branch that breaks a spec 04 test (for example, changing
  `time_split` to a random split) turns `test` red.
- Manual: a branch with a lint error turns `lint` red.
- Manual: a branch that adds a large CSV turns `data-guard` red.
- Manual: a clean branch is green on all four jobs, in under 10 minutes.

## Out of scope
Deployment, scheduled retraining, publishing models, and nightly runs on the
full dataset. Branch-protection settings on GitHub (requiring the four checks
before merging) are set by hand in the repo settings, not by this spec.
Type checking and a coverage threshold may be added later as a separate decision.
